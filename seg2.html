二、方法：四种循环，Agent 的时间系统

心跳循环（heartbeat）：短间隔持续运行，盯日志、查服务健康、扫漂移，适合监控类任务。定时循环（cron）：固定时间干批量活，晨间日报、每周依赖审计，适合例行公事。事件循环（hook）：外部事件触发、一次处理一个，PR 推送、CI 失败、消息到达，适合响应。目标循环（goal）：一直干到验收条件成立才停，重构、修 Bug、代码迁移，适合范围事先说不清的任务。

注意循环和 cron 的本质区别：cron 跑的是固定脚本，循环跑的是会读当前状态、自己选下一步的模型。脚本只会重复，循环会应变。

这套东西现在已经是开箱即用的功能。Claude Code 的 /goal 命令就是例子：你写一句"所有测试通过且 lint 干净"，Agent 就一轮一轮干下去。最妙的设计藏在细节里——每一轮结束后，换一个更小、更便宜的模型来判定"到底做完了没"。写代码的不许给自己判满分，这叫 maker ≠ checker。

还有一块拼图是记忆：循环的状态必须落在对话外面，一个 markdown 文件、一块任务板。因为 Agent 会忘，仓库不会忘。
